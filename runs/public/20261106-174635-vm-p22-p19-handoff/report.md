## 2. WF-09 실패: R05 입력 문제

- WF-09는 이관 문의를 같은 request_id로 두 번 보내는 시험이다. 두 번째 요청이 같은 티켓을 재사용(`duplicate: true`)하는지 본다. 그런데 첫 요청이 이관 조건을 채우지 못해 보완 질문으로 끝났다. 그래서 중복 처리 자체는 판정하지 못했다.
- 두 번째 요청은 233~256ms 만에 같은 보완 질문을 반환했다. 저장 응답을 재사용한 것으로 보이지만, LLM·티켓 0회는 확인하지 않았다.
- 조치: 질문 문장만 보완했다. 결제일·이용권·결제 수단·증상을 모두 넣었고, `cases/common.json`의 `input_change`에 이번 실패를 기록했다. 기대값은 바꾸지 않았다(도구 브랜치 커밋 `f30dc33`). 새 문장으로 VM에서 재시험해 별도 실행묶음에 기록한다.
