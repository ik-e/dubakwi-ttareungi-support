## 준비와 접근 복구

기존 웹 SSH는 연결돼 있었다. 별도 직접 SSH의 타임아웃을 기존 세션 장애로 확대했던 설명을 정정한다. Windows 전체 창 접근의 URL 인식 오류는 도구 초기화 후 정확한 SSH URL의 기존 탭 선택으로 해소됐다. 이후 새 로그인·키 발급 없이 기존 연결을 사용했다.

로컬 생성 파일4개는 CRLF 때문에 실제 바이트 해시가 안내값과 달랐으며 LF 정규화 시 일치했다. VM Linux에서 고정 커밋을 내려받아 다시 생성한 실제4파일은 모두 안내 해시와 일치했다. 업무 원본은 수정하지 않았다. 초기 컨테이너 이름 오인·sudo 인증 요구·스크립트 줄바꿈 SyntaxError는 반입 전 실패로 구분한다. 기존 Docker 권한으로 n8n 볼륨을 읽기전용 마운트한 온라인 SQLite 백업 integrity=ok와 config 사본을 확보했다. 복원은 시험하지 않았다.

전용4사본을 비활성 반입하고 실제 저장본의 Credential8참조를 대조했다. B01 팀키, B14/B15/B27과 handoff mock 내부키, L01~L03 기존 OpenAI다. 기존 Credential을 생성/회전하지 않았다. 사본 게시 뒤 두 HTTP 경로의 키 없음/틀린 키4요청은 모두403이었다.
