# VM Discord D06 타인 문의 접근 거부 종단 시험

- 실행 ID: `20261108-153000-vm-discord-d06-cross-owner` (KST)
- 실행 시각: 2026-11-08 15:30 KST
- 환경: 기존 PR36 Discord 봇, Jira 이슈 UI
- 범위: 현재 등록된 Discord 테스트 사용자로 다른 synthetic 사용자의 열린 문의에 접근 시도

## 사전 조건

- 현재 Discord 테스트 세션은 직전 본인 문의의 Jira 문맥에 내부 synthetic owner `citizen-c`로 기록되어 있었다.
- 접근 대상은 R05에서 생성된 열린 synthetic Jira 사례이며, Jira `dubakwi-case-context:v1` 기록의 owner는 `citizen-a`였다. 이 티켓은 같은 PR36 scope의 열린 To Do 상태였다.
- 문의 본문은 일반적인 기존 문의 후속 문장만 사용하고 실제 개인정보는 입력하지 않았다.

## 결과

| 단계 | 판정 | 관측 |
| --- | --- | --- |
| 타인 소유 `case_ref` 제출 | 통과 | 현재 등록 계정으로 타인 소유의 열린 문의 연결값을 기존 `/문의` slash command의 `case_ref` 필드에 입력했다. |
| 시민 응답 경계 | 통과 | 봇은 “문의 연결값을 확인할 수 없습니다”라는 일반 응답만 반환했다. 타인 문의 존재/내용은 공개하지 않았고 새 Jira 접수 키도 반환하지 않았다. |
| Jira 부작용 점검 | 통과(관측 범위 한정) | Jira 검색에서 시험 문구와 일치하는 신규 업무 항목은 없었다. Jira 티켓 생성이 관측되지 않았다. DB 요청/state 및 DLQ 행은 이번 실행에서 직접 조회하지 않았다. |

## 결론과 한계

D06의 타인 소유권 차단은 현재 Discord 등록 계정과 R05의 기존 synthetic 타인 사례를 사용해 실제 봇 경로에서 확인했다. Jira 검색으로 신규 티켓이 없음을 확인했다. 별도 Discord 플랫폼 계정으로 등록/미등록 응답을 비교하는 D05는 이번 실행에 포함되지 않았다. Jira 검색 결과는 신규 업무 항목 확인이며, DB 저장 효과가 없었다고 단정하지 않는다.
