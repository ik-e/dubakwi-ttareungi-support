## 공통 기준에서 바로 보완한 내용

1. Jira 종료 검사보다 기존 요청의 충돌·replay·진행/실패 게이트를 먼저 처리하도록 명시했다. 닫힌 티켓의 완료 요청도 replay이며 타인에게 이전 응답을 반환하지 않는다.
2. 선택 필드 추가만으로 동작 호환이 확보된다는 표현을 제거했다. 생산·소비 버전 묶음과 사본 선검사 후 활성화를 요구한다.
3. 상충하는 필수 사실은 값이 존재해도 재확인 대상으로 유지하고, 배정 호출0과 허용된 문맥 저장을 구분했다.
4. R01/R04가 함께 읽는 Jira 문맥 형식은 공통 인계가 필요함을 드러냈다. 구체적인 저장 형식·검증 주체·최신본 선택은 아직 미합의이므로 실제 연결의 의존성으로 기록한다. 새 위험의 운영 확인 응답도 미합의다.

CV23~25를 추가해 예제는 25개가 됐다. 예제 추가는 해당 동작의 실행 통과가 아니다. 이 결과로 공통 기준을 사용한 모의 개발은 시작할 수 있지만 현재 코드의 혼합 배포나 종단 성공을 승인할 수 없다.
