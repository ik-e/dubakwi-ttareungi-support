H24 label 검색 분기는 첫 검색 결과를 문의·소유권 검증 없이 재사용한다. 최신 Code로 같은 label의 다른 합성 티켓을 주면 known/reused로 돌아옴을 재현했다. 키 재사용 경로의 label 확인도 충돌한 두 원 ID를 구분하지 못한다. 원 ID·scope를 구분하는 키와 재사용 시 case/owner 검증, 다중 검색 결과 안전 실패 및 생성/조회/save의 일관된 식별 계약이 필요하다. 조회 지연에 의한 중복 생성과 이 식별 충돌은 별개다.

이미 완료된 상태는 현재 요청의 답변·문맥 저장 증거와 구분해야 한다. 외부 상태만 보고 context_saved를 확정하는 조건도 R04 검토 대상으로 남긴다. 최악11/13초 및 B27 15초는 아직 전체 SLA 통과의 근거가 아니며 실제 기한 안의 실행 측정이 필요하다.
