# 시험용 키 교체·사용처 동기화

2026-11-06 KST, R01. 사용자가 n8n 기존 dubakwi-team-key Credential에 새 값을 저장한 뒤 VM 비공개 동기화 도구에 같은 새 키를 숨김 입력해 인증과 파일 일치를 확인했다.


시험 support와 기존 운영 support 모두 빈 입력에서 신키400/구키403이었다. 400은 인증 후 invalid_input 검증 결과이며 정상 문의 성공이 아니다. 새 업무 요청·Jira 쓰기·기존 실패 요청 재전송은 하지 않았다.

VM 팀 키 환경파일·Discord 봇 팀키파일·현재 R02 비공개 인계를 동기화했다. 봇키0600/UID65532·인계0600과 세 사용처 값 일치를 확인했다. 이전 파일은Git밖0700/0600비공개백업으로보존했고키값은출력/커밋하지않았다. 과거실행원본/사본은증거로유지하며현재인계와구분한다.

R02/R04/R05는갱신된현재비공개인계를다시읽고기존프로세스/로컬환경에캐시한키를갱신해야한다. 구키는이제403으로거절된다. Discord봇은여전히미기동이며다음기동때새키파일을읽는다.

Jira API 토큰은변경하지않았다. 별도R02실행266/270의transition_unavailable·DB unknown·DLQ pending과G3미완료는유지한다. R04가Jira종료전환경로를관리하며이번키교체가종료문제해결을뜻하지않는다. [실행 대조 댓글](https://github.com/ik-e/dubakwi-ttareungi-support/pull/36#issuecomment-6677855026)을참조한다.
