## 보류

PR #13 `61dd421`의 실행 도구를 메모리 모듈로 읽고 임시 사례/가짜 transport로 다음 두 문제를 재현했다. 실제 HTTP·VM 호출은0이다.

1. 파일 before 초기화가503이어도 두 사례 Webhook 요청을 모두 전송하고 pass2건으로 집계한다. 파일 초기화 실패 시 종속 묶음을 blocked로 중단해야 한다.
2. 첫 사례 after 고장 해제가503이어도 두 번째 사례를 전송하고 pass로 집계한다. 해제 확인 전 후속 사례를 중단해야 한다.

R05 소유 실행 코드를 대리 변경하지 않았다. `--no-hooks`를 쓰는 입구4건은 해당 hook 경로를 사용하지 않으므로 시험 준비를 계속할 수 있다. P11-01은 현재 VM에 없는 citizen-a를 전제하므로 사례 입력 조정 또는 R04 호환 공급이 별도로 필요하다. `--check-logs`의 구현은 GET /logs의 logs 목록을 읽을 수 있지만 n8n/티켓 수동 확인을 자동 pass로 바꾸지 않는다.

PR #16 `329778c`는 실제 state/DLQ/handoff/Jira·전체 VM 검증·시간 기준이 미완료인 초안 본체다. 원본 B14와 모델 연결 부분 성공만으로 전체 JSON을 main의 P11 대신 병합하지 않는다. 두 PR 모두 초안 상태를 유지한다.
