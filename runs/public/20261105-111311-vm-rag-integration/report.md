## data-api에 필요한 인계

현재 Docker 컨텍스트의 전체 컨테이너/네트워크 별칭에 data-api가 없었다. n8n 내부에서 data-api:8800 health 호출은2500ms 타임아웃이다. 홈 경로 최대4단계에서 실행 원본을 찾지 못했고, 강사님 공개 저장소 HEAD는 이전80일차 원본 미확인 시점과 같은eb6937f다. R04 p09 후보에는 모의 JSON은 있으나 확인한 트리에 API 실행 구현이 없다. 다른 경로나 비공개 배포 위치의 부재까지 단정하지 않는다.

R04 또는 강사님에게 필요한 것은 실행 가능한 원본/이미지의 고정 버전, 실행/Compose 설정, 인증 방식, 모의 사용자 공급 방법이다. 기존 n8n 네트워크에서 내부 별칭data-api·포트8800으로 연결해야 한다. P11은 GET /employees/{user}와 POST /logs를 사용한다. 등록/미등록·장애의 응답 계약은 WORKFLOW-DESIGN을 따르며 데이터 JSON 존재만으로 API 준비 완료를 표시하지 않는다. 원본을 받으면 R01이 검토·기동하고 R05가 정상/미등록 사용자와 로그 기록을 확인한다. 새 대체 서버나 물리 DB는 임의로 추가하지 않았다.

B35 로그 타임아웃은 남아 있다. R03 상세 설계의 기존 VM 미검증 문구와 수동 색인 조건은 이번 증거의 역할 검토·반영 대상이다. 과거 실패와 보고서 해시는 수정하지 않는다. [가린 상세 결과](summary.json)를 참조한다.
