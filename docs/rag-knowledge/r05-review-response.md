# R05 검토 메모 대응 및 색인·검색 후속 계획

작성 2026-11-04. R03 작업 브랜치의 제안·초안이며 R05에게 전송하거나 팀에서 승인받은 기록은 아니다. 기존 사례의 이름과 이 브랜치 문서의 실제 제목이 다르므로 아래 매핑을 기준으로 공동 검토한다.

## R05의 4가지 요청

1. **보안 초동 안내:** `knowledge/public/privacy-security-guide.md`에 `계정 노출·침해 의심 시 공개 초동 안내`를 신설했다. 서울시설공단 2026-07-21 안내의 사칭 주의·의심 링크·112/118 및 따릉이 문의 경로를 요약하고 출처를 명시한다. 두바퀴 가상 이관은 별도 절이다. 이 문서가 개인의 침해 여부나 기관 조치를 확정하지 않는다.
2. **제한 문서:** `knowledge/restricted/handoff-policy.md`와 `knowledge/restricted/ticket-lifecycle.md`는 작성되어 있다. 둘 다 교육용 가상 정책이며 manifest에서 각각 `restricted`, 승인 대기·색인 비활성이다. 이는 권한 차단 구현이나 시험 통과를 뜻하지 않는다.
3. **노출 판정 표식:** 두 제한 문서에 각각 고유한 시험 표식을 추가했다. WF05에서는 시민 응답 본문·sources·반환 근거에서 해당 표식뿐 아니라 제한 doc ID·접근 수준·본문도 함께 검사한다. 표식 미노출만으로 권한 안전이 보장되지는 않는다. 담당자는 제한 자료 조회가 가능한 별도 양성 시험을 한다.
4. **권한 매핑:** manifest의 후보 값은 `public`/`restricted`다. 설계상 서버의 `citizen`은 `public`, `support`/`security`는 `public`+`restricted`를 허용한다. 서버 역할을 확인해야 하며 질문자가 보낸 값으로 권한을 결정하지 않는다. R04의 실제 매핑·인증·실행 검증은 미완료다.

## 개발과 확인 순서

1. 지식 문서의 manifest 해시를 갱신하고 문서·표식·시연 표시를 점검한다. 승인 대기와 색인 비활성 상태는 유지한다.
2. 청크 전처리에서 공식 초동 안내와 가상 이관이 구분되고, 제한 표식이 해당 문서에만 있는지 검사한다. 고유 표식은 비밀이 아니다.
3. n8n·벡터 저장소·임베딩 Credential·서버 역할 매핑을 확인하고 색인 및 검색 워크플로우를 구현한다. 검색 전에 권한별 partition을 선택한다.
4. 실제 환경에서 WF01/03/05/10/12와 TC04/09/10을 실행한다. WF03은 검색 결과와 최종 답변 근거 부족을 각각 기록한다. 승인 전 자료를 사용하는 경우 교육용 시연임을 명시한다.
5. R02에는 실제 절 제목과 Evidence 계약을, R04에는 역할 매핑과 노출 시험을, R05에는 위 기대값과 실행 결과를 전달해 검토한다. 전달·검토는 아직 수행하지 않았다.
