# PR #31 VM 색인 적용·원복 준비

작성: 2026-11-06 · 담당 R03 · **준비 계획; VM 적용·재색인·복구 시험 미실행**. 실제 환경 변경과 시험 창은 R01이 조율한다. 원본 경로와 공개 계약은 [RAG 공식 설계](../project/RAG-ARCHITECTURE.md), 기존 실행 방법은 [VM 색인 인계](r03-vm-index-handoff.md)를 따른다.

## 변경 범위와 구분

- PR #31 후보 `9e556a9`: 시민용 6개 지식·manifest·44개 청크 색인 스냅샷, 보안·환불 혼합 질문의 검색어 확장, 설계 문서. 직접 임베딩 비교는 n8n 검색이나 VM 적용 결과가 아니다.
- R02 `c6b4644`: L02의 출처 경위 표현 방지와 TC12 보완 질문 문구. 검색 지식 변경과 별개이므로 R01이 확정하는 각 적용 버전을 별도로 기록하고 결과를 분리한다. R02 실제 모델 비교는 로컬 시험이다.
- 기존 VM 11월 5일 검색 14/16과 실행 305 및 후속 실패 이력은 덮어쓰지 않는다. PR #24도 이전 설계서 파일명을 수정하므로 병합 시 rename 충돌·이전 파일 부활을 점검한다.

## 시험 창과 변경 전 확인

1. R01과 R02·R04·R05의 진행 중인 이관·고장·검색 시험이 종료된 것을 확인하고 색인·검색 변경/검증 시간과 담당자를 정한다. 동시 색인과 공용 workflow 동시 편집은 하지 않는다.
2. R01이 **실제 사용 중인** 색인·검색 workflow의 내보내기와 지식 스냅샷·설정·해시, 연결·활성 상태 및 workflow ID·Credential 연결 정보를 비공개로 보존한다. 저장소의 옛 커밋이 현행 VM과 동일하다고 가정하지 않는다. 키·원시 로그·사용자 정보는 공개하지 않는다.
3. VM n8n 버전, 같은 프로세스에서 Manual 색인과 게시된 검색이 메모리를 공유하는지, 내부 검색 Credential·Webhook 연결과 호출 경로가 올바른지 확인한다. 다른 사본을 병행 게시할 때 동일 Webhook 경로 충돌에 주의한다. 별도 CLI·다중 worker의 메모리 공유와 동시 색인은 검증되지 않았다.
4. 후보의 문서 해시와 44개 청크, 색인·검색 JSON과 연결 상태를 검토한다. 공개/제한 저장 공간과 교육용 가상 설정의 구분 및 승인 대기 상태를 유지한다. 실제 기관 승인이나 운영 정책으로 간주하지 않는다.

## 적용과 검증 순서

1. R01이 검토된 검색·색인 후보와 R02 support 변경의 적용 버전/해시, 환경별 Credential·workflow ID와 게시 경로를 확인하고 팀에 인계한다. 키는 비공개 경로로만 관리한다.
2. 정한 창에서 VM의 같은 n8n 프로세스에서 Manual 색인을 한 번 실행한다. 전체 노드 완료와 ready를 확인한다. OpenAI 임베딩 호출에 비용이 들며 색인 중에는 검색이 중단될 수 있다. 실행 기록에서 성공을 확인하기 전에는 HTTP 상태만으로 완료를 판단하지 않는다.
3. 인증된 검색 API 직접 시험: QR 기대 절, SR-WF12 보안 초동 안내, SR-TC04 환불 신청, WF03 empty, 시민 제한 문서·ID·본문·canary 비노출 및 허용 담당자 양성 대조를 수행한다. R05의 동일 16개 사례는 새 실행묶음으로 기존 결과와 구분한다.
4. P19 경유 시험은 R05·R02가 별도 기록한다. 사용자 API→B05→검색 권한, 최종 답변과 출처 표시를 확인하며 F-S1-03은 같은 QR 질문으로 재검증한다. TC12는 검색을 거치지 않는 R02 보완 질문 경로이므로 별도 판정한다.
5. 적용 커밋·JSON/지식 해시·설정·실행 시각·사례별 결과 및 실패를 가려 기록한다. 사용자 ID·비밀·원시 로그는 공개하지 않는다. R05 공식 판정과 R03 자체 확인을 구분한다.

## 실패 시 중단과 원복

- 현행 색인은 동일 메모리 키를 비우고 다시 쓰므로 이전 벡터가 자동 보존되지 않는다. 버전 alias 전환·즉시 롤백, 부분 재색인, 동시 색인 잠금은 구현되지 않았다. 검색 JSON만 되돌려서는 이전 색인이 복구되지 않는다.
- 실패·미완료 시 성공을 선언하지 않고 원인과 readiness·적용 버전을 R01에 알린다. building 또는 준비되지 않은 상태에서는 `index_not_ready` 등으로 검색이 차단되는지 확인한다. 예외 시 차단이 유지된다고 미리 단정하지 않는다.
- R01이 변경 전 보존한 **실제 VM의 이전 색인·검색 원본과 환경 연결**을 복원한 뒤, 같은 서버 프로세스에서 이전 색인본의 Manual 전체 재색인을 실행한다. ready와 시민/담당자 대표 검색을 확인하고 이전 결과 복구 여부를 새 기록으로 남긴다. Credential·workflow ID·Webhook 경로와 기존 공용 사본은 확인 후 보존한다.
- 이 원복 역시 임베딩 비용과 중단 시간이 들 수 있으며 VM에서의 복구 성공·걸린 시간은 미검증이다. 재색인 또는 검색 검증이 실패하면 검색 준비로 표시하지 않고 R01과 후속 조치한다. 기존 Jira·DB·DLQ·실패 요청은 수정하거나 재전송하지 않는다.
