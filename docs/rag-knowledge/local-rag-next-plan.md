- 확인 범위: 로컬 n8n 1.120.4에서 교육용 문서 44개 청크 색인, 내부 인증, 검색 결과와 공개·제한 분리, 일부 사례, 실패 및 재시작 후 재색인 시험. R02 P19의 B14 노드만 로컬 검색과 연결했다. R04 data-api 인증·R02 전체 흐름·R05 공식 판정·VM 시험은 미실행이다.

- 자료는 승인 전 교육용이며 `[실제 안내]`, `[가상 설정]`을 근거 본문에 유지한다. OpenAI Credential·내부 키는 저장소에 기록하지 않는다.

## 팀 공유 내용과 연결 경계

P11에서 B07~B32는 M01 mock이므로 RAG·티켓·이관을 실제 수행하지 않는다. P19는 P11의 배포 대상이 아니다.
- 원격 P11의 확인 시점 최신 HEAD는 `e48a66f`이며 `5113956` 실행에 대한 로컬 n8n 2.42.6 시험 증거가 추가돼 있다. 해당 기록은 11/11 통과를 보고한다. [PR #11](https://github.com/ik-e/dubakwi-ttareungi-support/pull/11)은 확인 시점에 열려 있으며 VM 시험과 R05의 공식 WF08/WF13 판정은 미실행이다. 배포 시 R01/R02가 최종 커밋·해시를 재확인한다.

### R04 P09의 가상 사용자와 사례 소유권

- R04 공유 기준 및 확인한 P09 브랜치에서 시민은 `public`, 담당자 `support-demo`/`security-demo`는 `public`과 `restricted`다. `unregistered-zz`는 등록하지 않는다. R04/R05 검토와 PR 전이므로 팀 확정으로 표시하지 않는다.
- 가상 소유권: `citizen-a`는 `T-DEMO-01`과 `case-a-closed`, `citizen-b`는 `T-DEMO-02`와 `case-b-open`을 소유한다. 확인한 records 기준 `case-a-closed`의 티켓은 `T-DEMO-03`, `case-b-open`은 `T-DEMO-02`다. 각 연락처는 가상 데이터다.
- 문서 검색 권한(public/restricted)과 특정 문의·티켓의 본인 소유권 확인은 다른 검사다. RAG에 제한 문서 검색 권한이 있다고 해서 타인의 문의를 조회할 권한이 생기지 않는다. 소유권 조회·거부는 R04/R02가 담당하며 R03은 시민의 제한 문서 근거·canary 누출이 없는지 시험한다.
- 과정 data-api의 `{name, dept}` 형태에 대한 최종 부서 매핑은 R02/R04와 정한다. 현재 P11 PR 설명은 매핑 전 IT팀도 citizen/public으로 처리한다고 명시한다. R03 제안은 **검증된 서버 측 허용 매핑이 없으면 restricted를 주지 않는 것**이며, 이를 확정된 팀 계약이나 현재 data-api 연결 결과로 표시하지 않는다.

## 우선순위별 다음 작업

1. **연결 가능한 단위를 먼저 인계 — 지금 가능.** R01/R02/R04/R05에 담당별 메시지 초안의 경로·사용법·검증 범위·남은 제약을 공유한다. R02에는 P11 첫 시험이 RAG와 무관하다는 점, R04에는 권한과 소유권의 경계를 함께 전달한다. 실제 메시지 전송은 사용자/팀의 공유 절차에 따른다.
2. **R04 → R02 → R03 권한 연결 — data-api 인계 후.** R04가 가상 사용자·조회 URL/인증·역할 응답을 제공하면 R02 B05가 확인한 `access_levels`가 검색 요청에 그대로 전달되는지 시민/담당자/미등록/조회 장애로 시험한다. P11 자체에는 검색 노드가 없으므로 검색 연결은 R02 P19 또는 향후 합의된 연결본을 기준으로 한다. 부서 매핑과 허용 권한은 R02/R04 검토 후 확정한다.
3. **R05 사례와 지식 평가 — 사례 확정 후.** WF01·WF03·WF05·WF10·WF12, TC04·TC09·TC10을 해당 사례의 조건과 검색/답변/조회 단계로 나누어 실행한다. citizen-a/b, T-DEMO-01/02 및 open/closed 소유권의 최종 기대값은 R05/R04가 확정하도록 요청한다. 문서·절·실제/가상 표시, 제한 canary, 근거 없는 질문과 답변을 따로 기록한다. 0.30 기준은 사례별 결과를 보고 조정하며 정확도·보안 통과로 단정하지 않는다.
4. **내구성·운영 조건 보완 — R03 주도, R01 환경 확인.** 저장소의 수동 색인 트리거와 검색이 실제로 같은 서버 프로세스의 메모리를 공유하는지 시험한다. 동시 색인 방지와 실패/중단 복구, 검색 요청 기한 및 n8n 2.x 호환성을 확인한다. Simple Vector Store의 재시작 시 재색인과 여러 worker/프로세스에서 공유되지 않을 수 있는 제한을 R01에 전달한다. VM 검증 전 실제 환경 성공으로 표시하지 않는다.
5. **R02 통합 및 R05 실행 — 연결본과 인증 전달 후.** R02 전체 상담 흐름에서 검색만 실제 연결하고 상태·Jira가 mock인 부분을 명확히 기록한다. R05가 공통·팀 사례를 실행하고, 실제 답변의 `[실제 안내]`/`[가상 설정]`, 출처, 오류 처리와 제한 근거 비노출을 확인한다. 실패와 미실행을 구분한다.
6. **VM 인계·이슈 정리 — 위 조건 충족 후.** R01에게 해당 커밋·파일·버전·Credential 종류·키 전달 경로·필요 네트워크·재색인·검증 결과를 인계한다. 팀 VM 시험은 별도 기록한다. 이슈 #9는 완료 기준을 확인한 뒤 닫고 PR #10은 리뷰·병합 여부에 맞게 처리한다. 아직 완료되지 않은 이슈나 PR을 닫지 않는다.

## 2026-11-05 R03 검색 평가 및 권한 연결 기준

사용자 결정에 따라 아래를 R03의 진행 기준으로 사용하고 팀에 전달한다. 이는 R04·R05 검토 완료, R05 공식 판정 또는 R02/R04 실제 서버 인가 연결 완료를 뜻하지 않는다.

- 검색 평가에서 기대 문서·절 포함 여부와 순위를 각각 기록한다. 기대 절이 1위가 아니더라도 포함되어 최종 답변에서 정확한 근거로 쓰였다면 순위만으로 실패로 단정하지 않는다. 최종 답변의 사실·조건·출처·실제/가상 구분을 함께 확인한다. 공식 사례의 최종 판정은 R05 담당이며 사례의 명시적 요구가 있으면 그 기준을 따른다.
- WF03은 검색 결과 empty 여부와 최종 답변의 근거 없는 주장 여부를 별도 기록한다. WF05 시민 결과에는 제한 doc ID·본문·출처·canary가 없어야 한다. 담당자 허용은 별도 양성 시험이다. 로컬 내부 검색 호출은 서버에서 검증된 시민 권한을 증명하지 않는다.
- 권한 경로: Discord 어댑터가 신뢰 가능한 사용자 식별자를 메인 흐름에 전달하고, R02 B05가 R04 서버 조회 결과를 확인한다. 서버가 시민이면 public, 허용된 담당자면 public+restricted를 부여하며 R02가 내부 인증 호출로 RAG에 전달한다. 자기소개나 질문의 역할로 권한을 부여하지 않는다. 미등록·조회 장애·잘못된 권한은 제한 검색 전에 거절/오류 처리한다. 티켓 소유권은 별도 검사다.
- P11의 support/security는 public 필수·restricted 선택이며 P09의 모의 담당자는 둘 다 가진다. public만 부여된 담당자는 RAG에서 public만 검색한다. 내부 Credential 보유 호출자의 access_levels를 RAG가 신뢰하는 현재 구조는 서버 측 인가가 완료됐다는 의미가 아니다.

## 2026-11-05 20:10 강사 피드백에 따른 우선순위
