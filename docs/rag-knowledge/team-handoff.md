# R03 RAG 작업 인계 메시지 초안

작성 2026-11-04. 아래 문구는 팀원이 실제로 배정되어 있는지 확인한 후 전달할 수 있는 초안이며, 아직 전송하지 않았다. 개발 역할 ID R01~R05는 실제 서비스 이용자 권한과 다르다.

## R01 — 환경·통합 담당에게

> RAG 색인·검색 기능을 준비하고 있습니다. 실제 워크플로우를 실행할 팀 n8n 접속 방법과 버전, Docker/VM 실행 환경, 지식 문서 마운트 경로, 사용할 임베딩 모델·Credential 등록 여부를 확인 부탁드립니다. 키나 토큰은 메시지나 Git에 올리지 말고 팀의 안전한 방식으로 연결해 주세요.
>
> 지식 자료 PR #4를 바탕으로 색인·검색 PR #6을 작성 중입니다. #4 병합 및 #6 기준 브랜치 변경 순서도 확인 부탁드립니다. 현재 제 환경에서는 Docker 엔진 연결에 실패했고 실제 n8n 실행은 확인하지 못했습니다.

## R02 — 메인 워크플로우 담당에게

> RAG 검색 요청은 `request_id`, `enabled`, `query`, 서버가 결정한 `access_levels`, `deadline_at`을 전달하고, 검색 결과는 `ok` / `empty` / `skipped` / `error`와 근거 목록을 반환하는 기존 설계를 기준으로 준비하고 있습니다.
>
> 결과 근거에서 문서·절·청크 ID·출처·버전과 함께 `[실제 안내]` / `[가상 설정]`을 보존해야 합니다. 현재 Evidence에 전용 유형 필드가 없는데, 우선 근거 텍스트의 표시를 유지할지, 별도 필드를 계약에 추가할지 확인 부탁드립니다. 실제 안내와 가상 설정이 같은 답변에 있으면 각각 표시해야 합니다.
>
> 검색 결과가 없을 때와 검색 자체가 실패했을 때의 본체 분기도 함께 맞추고 싶습니다. 실제 개인의 반납·환불·티켓 상태는 RAG로 확정하지 않습니다.

## R04 — 권한·연동 담당에게

> 사용자 결정은 시민이 `public` 6개만, 담당자가 `public` 6개와 `restricted` 2개를 검색하는 것입니다. 서버에서 `citizen` / `support` / `security` 등 실제 역할을 어디서 확인하고, RAG에 검증된 `access_levels`를 어떤 경로로 전달할지 확인 부탁드립니다.
>
> 질문에 “담당자”라고 적거나 클라이언트가 권한을 지정해도 restricted를 검색하지 않도록 검색 **이전**에 범위를 결정할 계획입니다. 인증 실패·역할 미확인 시 동작, 내부 Webhook 인증, 담당자가 두 partition을 함께 조회하는 방식을 같이 정하면 좋겠습니다.
>
> 제한 문서에는 노출 시험용 고유 표식이 각각 있습니다. 실제 권한 적용과 시험은 아직 수행하지 않았습니다.

## R05 — 시험·품질 담당에게

> P08 검토 메모 확인하고 다음과 같이 반영했습니다.
>
> 1. `privacy-security-guide`에 서울시설공단 공개 안내를 출처로 하는 `계정 노출·침해 의심 시 공개 초동 안내` 절을 추가하고, 가상 긴급 이관 절과 구분했습니다.
> 2. 담당자용 `handoff-policy`와 `ticket-lifecycle`을 작성했습니다. 둘 다 실제 따릉이 내부 규정이 아닌 교육용 가상 정책입니다.
> 3. 두 문서에 각각 `DUBAKWI-RESTRICTED-CANARY-01`, `DUBAKWI-RESTRICTED-CANARY-02`를 추가했습니다. 시민 응답의 본문·sources에 표식뿐 아니라 제한 문서 ID와 내용이 없는지도 함께 검사해 주세요. 담당자 접근 허용은 별도 양성 시험이 필요합니다.
> 4. manifest의 접근 수준 후보는 `public` / `restricted`입니다. 실제 서버 역할 매핑과 차단은 R04 연결 후 시험해야 합니다.
>
> 사례 제목은 [R05 검토 메모 대응](r05-review-response.md)에 정리했습니다. WF01/WF10은 `rental-guide`의 `QR 인식 또는 잠금 해제가 어려운 경우`, WF12/TC10은 공개 보안 초동 안내와 가상 이관 절, TC04는 가상 개별 요금·환불 이관 절, TC09는 반납 방법과 로그인·계정 찾기 절을 기대 근거로 제안합니다. 자전거 번호가 모든 기종에서 반드시 5자리인지는 확인하지 못했습니다.
>
> WF03 해외 이용 질문은 **검색 결과 0건인지**와 **찾은 문서가 질문에 답할 근거가 되는지**를 따로 기록하길 제안합니다. 실제 벡터 검색 전이라 `empty`를 확정하지 않았습니다.
>
> [검색·답변 시험 기대 결과](search-expected-results.md)에 28개 질문과 권한·표시 기준이 있습니다. 현재 결과는 예상값이며 검색 시험 결과는 아닙니다. 검토 후 수정할 점을 알려주세요.

## 현재 진행 상태

- 로컬 문서 준비와 청크 분리·해시 검사, 제한 표식 위치에 대한 자동 시험을 수행했다.
- 실제 n8n 색인·검색, 서버 인증과 권한 차단, 임베딩 및 WF03/WF05 실검색은 아직 수행하지 않았다.
- 지식 문서 manifest는 승인 대기 및 색인 비활성으로 유지한다.
