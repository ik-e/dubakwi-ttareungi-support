# R03 RAG 최종 인계 · R01

기준: 2026-11-07. 이 문서는 전달 시점까지 확인한 자료와 남은 작업을 정리하며, VM 현재 상태를 실시간으로 확인한 기록은 아니다.

## R03 준비 범위

- 시민용 지식 6개와 교육용 담당자 정책 2개, 문단 단위 청킹·임베딩·공개/제한 검색 및 근거 반환을 구현했다. 실제 안내와 가상 설정은 구분한다.
- PR #31 지식·검색 보완은 main `eb747df`에 병합됐다. R02 답변 생성 규칙 변경은 별도이며 VM의 현재 적용·색인 버전은 확인이 필요하다.
- 실행 305의 정상 1건은 R05가 public 근거와 QR 기대 절, 답변 근거 일치를 확인했다. 이는 전체 장애·복구·권한 통과를 뜻하지 않는다.
- 로컬 모의 권한·청킹·워크플로 검사 13건 및 지연 도구 모의 서버 검사 4건은 통과했다. 인증 HTTP 7건은 키 부재로 생략했다. 실제 검색 지연이나 VM 재색인·복구 성공을 의미하지 않는다.

## R01 후속 작업

1. R02·R04·R05와 공용 환경 작업 시간을 조율하고 실제 VM의 색인·검색·본체 버전, Credential 연결 및 기존 적용본을 확인·보존한다. [적용·원복 계획](p31-vm-index-recovery-plan.md)을 따른다.
2. PR #31 적용과 수동 재색인을 판단·실행한 뒤 QR, WF12, TC04, WF03 등을 검색 API에 직접 시험하고 P19 경유 결과는 별도 기록한다. 기존 결과와 실패 기록을 보존하고 R05에 공식 재판정을 맡긴다.
3. 사용자 조회→B05→RAG에서 시민 public 전달과 제한 문서·ID·본문·canary 비노출을 확인한다. 허용된 담당자 restricted 양성 대조도 별도로 실시한다.
4. 실행 #796의 검색 시간 약 3,018ms에 대한 원인을 단계별 반복 측정한다. 제한시간 변경은 R02·R05와 전체 시간 예산을 함께 검토한다. 로컬 개발용 측정 도구와 제약은 [검토 기록](r03-evidence-review-20261107.md)에 있다.
5. 재시작·재색인 복구를 실제 환경에서 검증한다. 현재 메모리 색인은 즉시 롤백되지 않으므로 이전 색인본을 보존하고 필요 시 전체 재색인해야 한다. PostgreSQL·pgvector 벡터 저장 및 백업·복원은 기존 상태·DLQ DB와 구분한 향후 작업이다.
6. F-S1-03 출처 표현, TC12, TC14는 각각 지식·본체 답변·상태 경로를 구분해 담당자 수정본과 R05 결과를 확인한다. WF-01 개별 결과와 일부 합계 표현의 차이도 R05에게 확인한다.

## 전달 시 주의

기존 Jira·DB·DLQ 및 실패 요청은 임의 변경하거나 재전송하지 않는다. 키·사용자 식별자·원시 실행 기록은 공개 자료에 넣지 않는다. 최종 제출·발표 자료와 개인 소감은 R01 및 본인 확인을 거친다.
