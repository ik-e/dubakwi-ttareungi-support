# 로컬 n8n RAG 개발 기록

2026-11-04 · P10/P16 로컬 개발 브랜치. 이 문서는 진행 상태이며 실제 실행 증거를 대체하지 않는다.

## 개발 기준

- 로컬 n8n, OpenAI `text-embedding-3-large`, Simple Vector Store. 비밀은 사용자가 n8n Credential에 등록한다.
- 승인 대기 문서는 교육용으로만 사용하며 실제 개인정보를 넣지 않는다. 저장소 재시작 시 재색인한다.
- 서버가 확인한 시민은 공개, 담당자는 공개·가상 제한 지식을 검색하도록 설계한다. 실제 서버 인증과 권한 강제는 연결 전이다.

## 시작 상태

- 사용자 요청으로 별도 브랜치를 생성했다. 기존 P08/P10 초안을 기반으로 한다.
- 로컬 n8n 실행이 확인되지 않아 프로젝트 폴더 밖의 사용자 로컬 디렉터리에 설치를 시도한다. 설치·실행·Credential·API 연결의 성공 여부는 아직 확인되지 않았다.
- workflow JSON, 실제 색인·검색·재시작·권한 차단 시험은 미완료다.

## 로컬 설치 및 실행 결과

- npm에서 n8n 2.46.4 설치를 두 차례 시도했으나 Windows x64에서 Linux arm64 의존성 `@napi-rs/canvas-linux-arm64-musl`의 `EBADPLATFORM` 오류로 실패했다.
- 별도 사용자 로컬 폴더에 n8n 1.120.4를 설치하고 버전 명령을 확인했다. 이 버전은 로컬 개발 시험용이며 팀 버전과의 호환성은 확인되지 않았다.
- 기존 n8n 설정을 사용하지 않는 별도 사용자 폴더, `127.0.0.1:5678`으로 실행했으며 `/healthz` HTTP 200을 확인했다.
- OpenAI Credential 등록과 실제 API 사용 가능 여부는 확인하지 않았다. API 키를 소스·Git·로그·채팅에 입력하지 않는다.
- 실제 색인·검색 워크플로우 구현 및 n8n 가져오기·벡터 검색·재시작·서버 권한 시험은 미완료다.

### 사용자 Credential 등록

로컬 n8n의 첫 화면에서 사용자 본인이 계정을 설정한 다음 Credentials에서 OpenAI 자격 증명을 만들고 개인 API 키를 직접 입력한다. 키를 공유하거나 PR에 입력하지 않는다. 사용 가능한 모델과 비용은 연결 후 확인한다.

## R01 VM 준비 사항과 사용자 Credential 등록 공유

2026-11-04 사용자 전달: 로컬 n8n OpenAI Credential을 등록했다고 함. 키 값·계정·실제 API 호출·모델 접근 및 과금 성공은 확인하지 않았다. 로컬 n8n `/healthz` HTTP 200을 다시 확인했다.

R01의 [PR #12](https://github.com/ik-e/dubakwi-ttareungi-support/pull/12)는 기존 팀 VM n8n·볼륨·네트워크 관측과 운영 경로 준비에 대한 초안이다. 사용자 전달과 PR 본문 기준 첫 입구 시험 WF08/WF13은 RAG 완료를 기다리지 않는다. P11 워크플로우의 VM 가져오기·data-api 연결·Credential 생성·VM에서의 사례 실행은 PR 내용상 미실행이다. 개인 로컬 n8n과 팀 VM은 별도 환경이며 동일한 인스턴스나 동일한 Credential로 가정하지 않는다.

### 다음 R03 작업 순서

2. 로컬 n8n에 지식 색인·검색 워크플로우를 작성하고 사용자가 등록한 Credential의 동작과 임베딩 모델 접근을 확인한다. API 키 값은 확인하거나 기록하지 않는다.
3. 시민/담당자 권한별 검색·실제/가상 구분·빈 결과/장애·재시작을 시험한다. 로컬 평가 도구의 모의 권한은 실제 인증이 아님을 유지한다.
4. 기능과 로컬 시험 결과를 정리한 뒤 팀 VM과의 버전·저장소·Credential·배포 경로를 별도로 확인한다. R01의 첫 입구 시험을 기다리거나 변경하지 않는다.

### R05 첫 입구 시험 안내 반영

사용자가 전달한 R05 검토 기준: WF08과 WF13의 빈 질문·501자 사례는 사용자 조회 전에 종료되므로 data-api 없이 부분 시험할 수 있다. WF13 미등록 사용자는 data-api 사용자 조회 준비 이후 시험한다. 실제 시험 시작에는 VM 주소·키의 비공개 전달, 배포 커밋, 운영 Webhook 활성화, n8n 실행 기록 확인 방법이 필요하다.

현재 P11 골격에는 실제 LLM·티켓 노드가 없으므로 n8n 실행 노드 목록에서 B04·M01 등 이후 단계 미실행을 확인하는 것은 골격 단계의 증거다. LLM·티켓 노드가 추가되면 다시 시험해 실제 호출·티켓 수 변화를 확인해야 한다. B35 기록은 data-api가 없으면 저장되지 않아 초기 증거로 사용하지 않는다. R03 로컬 RAG 준비는 첫 입구 시험과 병행하며 이 기록은 실제 VM 시험 통과를 뜻하지 않는다.

R05의 사례 수정 대상 브랜치는 `r05/p06-flow-cases`다. 이전 `r05/p06-flow-format`은 사용자 전달상 사용 종료다. 해당 브랜치 병합과 flow.py 실제 실행 여부는 별도로 확인한다.

### R02 PR #11의 R03 검토 초안

2026-11-04 PR #11의 `B05` 코드와 설명을 확인했다. 임시 접근 수준 `public`·`restricted`는 현재 RAG manifest의 값과 일치한다. 과정 data-api의 `name`·`dept`만 있는 응답은 부서명만으로 담당자 권한을 판단하지 않고 `citizen` + `public`으로 처리하는 제안에 동의한다. 실제 서버 역할과 식별 신뢰는 R04와 연결 시험 전이다.

주의: B05의 팀 형식 검증은 citizen에 restricted를 허용하지 않지만, support/security가 `public`만 가진 조합도 허용한다. 이는 안전한 최소 권한으로 동작할 수 있으나 사용자 결정인 담당자 공개+제한 검색을 항상 보장하지 않는다. R03 권장안은 검증된 담당자에게 정확히 두 값이 공급되는지 R04 매핑에서 보장하거나, 누락은 오류로 취급하는 것이다. 실제 RAG 검색 및 차단은 미구현이므로 PR #11의 골격 시험으로 RAG 권한 통과를 주장하지 않는다.

R02 보고에 따르면 P11의 로컬 Code 및 n8n Webhook 시험은 통과했으나 VM 배포와 공식 WF08/WF13 판정은 미실행이다. 이는 R03 로컬 RAG 환경의 실행 결과와 별개다.

### R04 사용자·권한 연결 인계 계획 반영

2026-11-04 사용자 전달: R04가 P09 모의 시민·담당자 계정, B05 서버 사용자 검증, 시민 public·등록 담당자 허용 restricted, 미등록 400·조회 장애 503, Discord ID 연결을 최우선으로 준비한다고 공유했다. 실제 JSON·응답 예시·시행 결과와 통합 준비 완료는 아직 전달되지 않았다. R03은 등록 역할을 클라이언트 자칭과 분리해 받은 `access_levels`로 검색 전 범위를 선택하고, R04 실제 계약·인증 및 오류와 대조한다. 사용자 확인 실패나 오류를 성공적인 시민 조회 또는 담당자 권한으로 가정하지 않는다.

R04는 TC10 조회 전용 고장, 생성 응답 유실·저장 실패와 수동 복구 시험 경로도 준비 예정이라고 했다. R03은 실제 호출·실패 결과 수신 전 관련 검색·이관을 통과했다고 표시하지 않는다. R04 개인 Jira 기존 티켓 조회가 확인되었다는 공유는 팀 VM 연동·신규 생성 완료를 뜻하지 않는다.

### R02 검색 연결·R04 fixture 공유 반영

2026-11-04 R02가 검색 호출 계약을 공유했다. 내부 검색은 POST `/webhook/dubakwi-search`, Header Auth의 `X-Internal-Key`를 사용하며 시민 입구 `X-Team-Key`와 구분한다. 내부 인증 Credential 명칭 `dubakwi-internal-key`는 설정 이름이고 값은 비공개다. 요청의 `request_id`를 응답에 유지하고 status는 `ok`·`empty`·`skipped`·`error`다. Evidence 필수 필드 `doc`, `section`, `chunk_id`, `text`, `score`, `access_level`, `version`을 유지하고 text 안에 `[실제 안내]`·`[가상 설정]`을 넣는다. 사용자 결정에 따라 시민 답변에도 해당 표시를 보여 주는 것을 기본안으로 하되 최종 답변 생성은 R02 담당이며 실제 연결은 미구현이다. Request.user는 Discord ID가 아니라 어댑터가 서버 등록 사용자로 바꾼 값이라는 R02 설명을 따른다.

R04의 `r04/p09-fixtures` 사용자 5명은 citizen-a/b/c에 public, support-demo·security-demo에 public과 restricted를 부여해 R03 기준과 일치한다. 파일의 fixture만 확인했으며 실제 서버에서 사용자 공급·인증·RAG 검색 전 차단이 동작한다는 뜻은 아니다. R04 P12는 상태 저장/Jira 미연결 시 성공 처리하지 않는 비활성 골격으로 실제 저장·생성은 미완료다. 두 브랜치는 R04 소유이며 임의 병합하지 않았다.

로컬 n8n DB에서 Credential 종류·개수만 읽어 `openAiApi` 1개 등록을 확인했다. 키 값·개인 식별 정보는 읽지 않았고, 실제 모델 API 호출 성공·과금은 미확인이다.

## OpenAI 임베딩 API 로컬 연결 시험

2026-11-04 로컬 n8n에 등록된 OpenAI Credential을 연결한 임시 수동 워크플로우에서 짧은 테스트 문장으로 `text-embedding-3-large` API 요청을 실행했다. HTTP 요청 노드와 요약 노드가 성공해 실제 API 연결을 확인했다. API 키와 벡터 원문은 저장소에 기록하지 않는다. 이 시험은 벡터 저장소·RAG 검색·권한 기능의 성공을 뜻하지 않는다. 테스트 워크플로우는 로컬 전용이며 서비스 파일로 내보내지 않았다.

## 로컬 벡터 저장·검색 연결 시험 (1건)

2026-11-04 로컬 n8n 1.120.4의 임시 수동 워크플로우에서 OpenAI `text-embedding-3-large`와 Simple Vector Store를 연결했다. 교육용 QR 대여 문장 1건을 삽입한 뒤 같은 실행에서 질문 `따릉이 QR 대여`로 검색하여 `rental-guide` 1건, 유사도 약 0.707을 확인했다. Credential 값과 벡터는 기록하지 않았다.

이것은 로컬 단일 실행의 연결 검증이다. 실제 8개 문서 전체 색인, 서버의 두 워크플로우 간 메모리 공유, 시민·담당자 인증 및 검색 전 접근 제한, 오류/재시작 복구, WF 사례·성능 비교는 검증하지 않았다. 검증용 워크플로우는 임시 로컬 자료이며 서비스 산출물이 아니다.
