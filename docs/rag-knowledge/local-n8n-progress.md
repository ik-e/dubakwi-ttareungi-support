### R02 PR #11의 R03 검토 초안

2026-11-04 PR #11의 `B05` 코드와 설명을 확인했다. 임시 접근 수준 `public`·`restricted`는 현재 RAG manifest의 값과 일치한다. 과정 data-api의 `name`·`dept`만 있는 응답은 부서명만으로 담당자 권한을 판단하지 않고 `citizen` + `public`으로 처리하는 제안에 동의한다. 실제 서버 역할과 식별 신뢰는 R04와 연결 시험 전이다.

주의: B05의 팀 형식 검증은 citizen에 restricted를 허용하지 않지만, support/security가 `public`만 가진 조합도 허용한다. 이는 안전한 최소 권한으로 동작할 수 있으나 사용자 결정인 담당자 공개+제한 검색을 항상 보장하지 않는다. R03 권장안은 검증된 담당자에게 정확히 두 값이 공급되는지 R04 매핑에서 보장하거나, 누락은 오류로 취급하는 것이다. 실제 RAG 검색 및 차단은 미구현이므로 PR #11의 골격 시험으로 RAG 권한 통과를 주장하지 않는다.

R02 보고에 따르면 P11의 로컬 Code 및 n8n Webhook 시험은 통과했으나 VM 배포와 공식 WF08/WF13 판정은 미실행이다. 이는 R03 로컬 RAG 환경의 실행 결과와 별개다.

### R02 검색 연결·R04 fixture 공유 반영

2026-11-04 R02가 검색 호출 계약을 공유했다. 내부 검색은 POST `/webhook/dubakwi-search`, Header Auth의 `X-Internal-Key`를 사용하며 시민 입구 `X-Team-Key`와 구분한다. 내부 인증 Credential 명칭 `dubakwi-internal-key`는 설정 이름이고 값은 비공개다. 요청의 `request_id`를 응답에 유지하고 status는 `ok`·`empty`·`skipped`·`error`다. Evidence 필수 필드 `doc`, `section`, `chunk_id`, `text`, `score`, `access_level`, `version`을 유지하고 text 안에 `[실제 안내]`·`[가상 설정]`을 넣는다. 사용자 결정에 따라 시민 답변에도 해당 표시를 보여 주는 것을 기본안으로 하되 최종 답변 생성은 R02 담당이며 실제 연결은 미구현이다. Request.user는 Discord ID가 아니라 어댑터가 서버 등록 사용자로 바꾼 값이라는 R02 설명을 따른다.

R04의 `r04/p09-fixtures` 사용자 5명은 citizen-a/b/c에 public, support-demo·security-demo에 public과 restricted를 부여해 R03 기준과 일치한다. 파일의 fixture만 확인했으며 실제 서버에서 사용자 공급·인증·RAG 검색 전 차단이 동작한다는 뜻은 아니다. R04 P12는 상태 저장/Jira 미연결 시 성공 처리하지 않는 비활성 골격으로 실제 저장·생성은 미완료다. 두 브랜치는 R04 소유이며 임의 병합하지 않았다.

로컬 n8n DB에서 Credential 종류·개수만 읽어 `openAiApi` 1개 등록을 확인했다. 키 값·개인 식별 정보는 읽지 않았고, 실제 모델 API 호출 성공·과금은 미확인이다.

## OpenAI 임베딩 API 로컬 연결 시험

2026-11-04 로컬 n8n에 등록된 OpenAI Credential을 연결한 임시 수동 워크플로우에서 짧은 테스트 문장으로 `text-embedding-3-large` API 요청을 실행했다. HTTP 요청 노드와 요약 노드가 성공해 실제 API 연결을 확인했다. API 키와 벡터 원문은 저장소에 기록하지 않는다. 이 시험은 벡터 저장소·RAG 검색·권한 기능의 성공을 뜻하지 않는다. 테스트 워크플로우는 로컬 전용이며 서비스 파일로 내보내지 않았다.

## 로컬 벡터 저장·검색 연결 시험 (1건)

2026-11-04 로컬 n8n 1.120.4의 임시 수동 워크플로우에서 OpenAI `text-embedding-3-large`와 Simple Vector Store를 연결했다. 교육용 QR 대여 문장 1건을 삽입한 뒤 같은 실행에서 질문 `따릉이 QR 대여`로 검색하여 `rental-guide` 1건, 유사도 약 0.707을 확인했다. Credential 값과 벡터는 기록하지 않았다.

이것은 로컬 단일 실행의 연결 검증이다. 실제 8개 문서 전체 색인, 서버의 두 워크플로우 간 메모리 공유, 시민·담당자 인증 및 검색 전 접근 제한, 오류/재시작 복구, WF 사례·성능 비교는 검증하지 않았다. 검증용 워크플로우는 임시 로컬 자료이며 서비스 산출물이 아니다.

## 2026-11-04: 실제 임베딩 및 워크플로우 초안

- `text-embedding-3-large`와 로컬 Simple Vector Store를 이용해 **승인 대기 교육용** 8개 문서의 청크 44개(공개 36, 제한 8)를 한 번의 임시 실행에서 색인했다. 한글이 정상 보존되고 공개 QR 검색에서 `rental-guide` 상위 3개를 확인했다. 이는 CLI 한 프로세스 안에서의 시험이며, 서비스 검색 API의 통과를 뜻하지 않는다.
- 별도 분리 시험에서 공개 컬렉션의 상위 5건은 모두 public이고 제한 표시 문자열은 없었으며, 제한 컬렉션의 결과에는 restricted와 표시 문자열이 있었다. 이 시험은 실제 사용자 로그인·서버 인가나 API 응답의 누출 시험이 아니다. 임시 시험에서 제한 검색이 공개 결과 항목마다 반복 실행되는 결함이 관찰돼 워크플로우 초안에는 공개 결과를 한 항목으로 모으는 단계를 넣었으나 수정본의 실제 Webhook 시험은 아직 하지 않았다.
- `workflows/dubakwi-index.json`, `workflows/dubakwi-search.json`은 **비활성 교육용 초안**이며 로컬 n8n에 가져오기만 했다. 저장소에는 Credential ID와 키를 넣지 않았다. 색인 문서가 바뀌면 `python scripts/dev/refresh_demo_index.py`로 승인 상태·해시를 검증해 교육용 스냅샷을 갱신한다. 이 명령은 실제 승인 처리를 하지 않는다.
- 검색 초안의 최소 점수 0.25는 시험용 가정이다. QR 검색의 실제 점수는 약 0.26~0.32였으며, 정확도와 WF03 빈 결과를 평가해 조정하기 전에는 확정 기준으로 사용하지 않는다.
- **미완료**: 검색 Webhook Header Auth Credential 연결 및 실제 요청 시험, 시민·담당자 API 권한/누출 시험, 오류·시간 초과·빈 결과, 반복 색인과 재시작 복구, R02/R04/R05 통합. 코드에 있는 역할 판정은 인증된 내부 호출자가 제공한 access_levels를 신뢰하며, 최종 사용자 확인은 R02/R04의 책임이다.
- 현재 색인은 기존 컬렉션을 먼저 비우므로 도중에 실패하면 부분 색인이 남을 수 있다. 준비 상태 감지와 실패한 후보의 격리도 아직 없어 서비스에 연결하거나 배포하지 않는다. 승인 대기 자료와 가상 문서만 교육용으로 사용한다. 이슈 #9와 PR #10은 완료 조건 미달로 열린 상태를 유지한다.
- 로컬 자동 검사: `python -m pytest scripts/test/test_prepare_rag_chunks.py scripts/test/test_rag_local_evaluation.py scripts/test/test_n8n_rag_artifacts.py -q` → 11건 통과. 이 중 워크플로우 검사는 JSON 구조만 확인하며 실행 시험의 대체물이 아니다.

## 2026-11-04: 로컬 HTTP 검색·복구 시험 갱신

이 절은 위 초안 단계의 미완료 기록을 갱신한다. 정확한 절차와 제한은 [로컬 n8n 실행 및 인계](local-n8n-runbook.md)를 참조한다.
