## 1. 주제 한 줄

**“따릉이 운영기관의 시민 이용자를 위한, 모든 정상 신규 문의의 티켓 접수·근거 기반 자동 답변·담당자 연결 자동화”**

이용자는 따릉이 시민이며 직원은 티켓을 받는 담당자로 설정한다. 답변 가능한 문의는 근거 답변·검증 후 티켓을 생성·종료하며, 정보가 부족하면 보완하고 담당자 처리가 필요하면 해당 티켓으로 연결한다. 이 방향은 사용자와 합의했으며, 아래 문의 유형·담당 역할·구성은 팀 검토를 위한 제안이다.

**입구 · 뒷단 조합** ([주제 가이드 — 공개본 제외 자료](../../docs/PUBLIC-SOURCES.md) 7절): ☐ A 기본형 (팀 웹훅 · data-api) ☐ B 메신저 + 헬프데스크형 (텔레그램 · Zammad) ☐ C 자체 웹앱형 (웹 화면 · FastAPI)

- 사용자 결정(2026-11-03): 티켓 관리 뒷단은 Jira를 사용한다. 이용자 입구는 Discord로 채택하고 공통 시험용 팀 웹훅은 유지한다. Discord 어댑터가 공통 계약을 변환하며 공통 검증은 A/data-api 경로, 실제 티켓 처리는 Jira 어댑터로 분리한다. 제공 기능 확인 전 재사용을 확정하지 않는다. Jira 연결·프로젝트 설정은 미완료이며 조합 표기·강사 확인은 남아 있다. 추가 저장 관리는 최소 처리 상태·n8n 실행 기록·DLQ로 한정한다. PostgreSQL 3테이블 제안은 채택하지 않으며 물리 저장 방식은 기능 확인 후 결정한다.
- Discord 결정(2026-11-03): 팀이 사용하는 Discord에서 슬래시 명령·본인 전용 응답으로 모의 시민 문의를 받는다. Python Gateway 봇→기존 n8n Webhook 기본안이며3초 초기 응답과 최종 업무 응답을 분리한다. 팀 계정 매핑은 시민 본인 인증이 아니다. 세부 원본은 [시스템2.1](SYSTEM-DESIGN.md#21-discord-이용자-채널)·[워크플로우6.6](WORKFLOW-DESIGN.md#66-discord-입출구-어댑터)다. 봇·서버·토큰·실연결은 미준비다.
- Jira 어댑터는 R04가 맡고 R02가 본체를 연결한다. 공통 계약과 data-api 검증 경로를 유지하며 실제 서비스 장애·계정 미준비 시의 시연 대체 경로는 개발 계획에 기록한다.

모든 정상 신규 문의는 티켓화한다. 보완 응답의 case_ref를 다음 요청에 전달해 같은 티켓을 유지하며,같은 요청 재전송은 저장 결과를 재사용한다. 연결값 누락은 새 문의이고 소유자/종료 상태를 확인하지 않은 자동 병합·재개는 하지 않는다. 인증 실패·잘못된 입력·주입 공격은 접수 전에 검사·거절하며 업무 티켓을 생성하지 않는다. 권한 없는 정보는 답변·티켓·알림에 노출하지 않는다.

기존 W01·W02·W04·W08·W09와 C01·C04는 보완 질문·기존 조치·개인정보·재현 정보·담당자 전달 항목의 참고로 활용한다. 직원·협력업체가 별도로 요청하는 작업 지원은 이번 범위에 포함하지 않는다.

자동 답변하면 안 되는 경우:

- 적용 가능한 근거가 없거나 답변 검증에 실패한 경우: 근거 없는 생성을 중단하고 담당자 이관. 근거가 없으면 sources는 빈 목록으로 반환한다.
- 보완 한도에 도달한 경우: attempt 3에서 티켓을 포함한 담당자 이관.
- 개별 요금 정정·환불·안전 판단·실제 작업 등 담당자 판단·권한이 필요한 경우.
- 긴급 보안 사고·신체 위험 등 즉시 사람 검토가 필요한 경우. 필요한 근거 안내는 함께 제공하되 자동 답변만으로 종료하지 않는다.
- 권한 없는 문서·타인 기록 요청, 주입 공격, 판별·검증 LLM 장애 등 허용 조건을 충족하지 못한 경우: 권한 없음·차단·정해진 대체 경로를 적용한다.

실제 환불·요금 변경·강제 반납·원격 잠금 해제·출동/배차·정비/출고 승인은 수행하지 않는다. 자동 종료는 안내 제공 완료를 뜻하며 실제 문제가 해결됐다는 판정이 아니다. 티켓 생성·종료·담당 전달이 실패하거나 미확인이면 성공으로 표시하지 않는다.

기존 앱에도 상담·신고·반납 안내가 있다. 이번 구현은 자유 서술의 정보 보완·근거 안내·맥락 있는 담당 연결을 시험하며 실제 처리시간 절감·기존 기능의 부재는 성과나 사실로 주장하지 않는다. 기존 확인 범위는 [jso 조사 통합 — 공개본 제외 자료](../../docs/PUBLIC-SOURCES.md)과 [csj 조사 통합 — 공개본 제외 자료](../../docs/PUBLIC-SOURCES.md)을 따른다.
