    06 / 문제와 다음 단계

    검색 이후의 답변과 복구도 확인합니다

    발견한 문제

    시민 답변에 내부 출처 메모가 섞였고, 다른 실행에서는 검색이 3초 제한을 넘어 이관됐습니다(약 3,018ms). 단계별 지연 원인은 미확인입니다.

    변경과 재시험

    R03 지식·검색과 R02 답변 생성 규칙은 별도 변경입니다. PR #31은 main에 병합됐으며 VM 적용·재색인과 재시험 상태는 R01 인계로 확인해야 합니다.

    시민 제한 요청 차단은 검색 단계의 권한 시험과 구분합니다. 즉시 색인 롤백 기능은 없으며, 실패 시 이전 색인본의 전체 재색인이 필요합니다.

    전체 연동 PR #36 · RAG 보완 PR #31 · R01 내용 확인 및 최종 편집 전

    07 / 팀장 인계

    R01이 이어서 확인할 작업

    색인·답변 재시험

    VM의 적용 버전을 확인하고 시험 시간을 조율한 뒤, 동일 질문을 검색 API와 전체 상담 흐름에서 각각 다시 시험합니다. 기존 결과와 실패 기록은 보존합니다.

    권한과 복구

    시민·담당자 권한이 실제 사용자 조회부터 검색까지 전달되는지, 재시작 후 재색인과 검색 복구가 되는지 확인합니다.

    느린 검색의 원인

    임베딩·검색·통신 시간을 나눠 측정한 뒤 전체 응답 시간 기준과 함께 판단합니다. 현재 원인은 확인되지 않았습니다.

    장기 개선

    PostgreSQL·pgvector 벡터 저장과 백업·복원은 별도 설계 및 검증 대상입니다. 기존 문의 상태 DB가 곧 RAG 저장소를 뜻하지 않습니다.

    공용 VM 수정·실제 권한 재시험은 팀이 정한 작업 시간에 진행 · 전체 연동 기록
