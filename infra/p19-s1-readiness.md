## 1 이번 목표와 범위

등록 사용자의 Discord 문의 → 서버 사용자·권한 확인 → 실제 AI·RAG → 실제 Jira 생성·안내 종료 → DB 최종 응답 저장 → 같은 사용자에게 비공개 응답을 정상 문의 1건으로 연결한다. 환불·강제 반납 등의 실제 업무 집행 성공을 뜻하지 않는다.

먼저 실제 시험 Webhook에서 동일 업무 흐름을 성공시킨 뒤 Discord를 연결한다. 추가 UX·도움말·재개 엔진은 이번 목표에 넣지 않는다. 정상 1건의 성공과 권한·중복·실패·시간·복구의 전체 판정은 분리한다.

## 4 역할별 이번 행동과 인계

기존 소유권은 헌장을 따른다. 아래는 이번 통합의 실행 분담이며 담당 표를 새로 정의하지 않는다.

- R01: 위G0~G2/G4 환경 준비, 막힌 결정 해소, 적용/원복 기록. VM 준비를 팀원에게 떠넘기지 않는다.
- R02: 확정 버전의 P19를 실제 하위 기능에 연결하고 정상 Webhook 실행. 최초 실패 노드·실행 ID·가린 입출력 차이 인계.
- R03: 시민 public 고정 질문1개·기대 근거·색인/검색 버전을 준비하고 실제 검색 가능 여부 확인.
- R04: Jira 생성/bind/문맥/종료/저장 경계와 Discord 매핑·응답 변환·비공개 전송 확인. 신규 복구 엔진이나 본체 업무 로직 사본을 만들지 않음.
- R05: 준비 완료 인계 후 같은 질문으로 각 구간 증거를 대조. normal/failure_handling/recovery·not_implemented를 분리.

각 담당자는 AI로 최신 상태 확인·담당 구현/검사·실패 원인 분석을 진행하되, 사람은 권한/비밀 입력과 실제 결과를 확인하고 인계한다. 계획이나 AI의 완료 문장만으로 종료하지 않는다. 막힌 범위 외 독립 작업은 계속한다.

보고는 대상 버전 / 실제 완료 구간 / 실행 ID·증거 / 막힌 이유 / 필요한 담당 조치만 남긴다. 다른 PR에 상세가 있으면 링크하며 원문을 중복 작성하지 않는다. R01이 전달받은 합의를 PR/원장에 취합한다.

## 5 목표 완료 증거와 후속 시험

PR #36의 첫 목표 종료 조건이다. 이 증거가 없는 단계는 완료로 체크하지 않는다.

1. 실제 시험 Webhook의 정상 요청이 실제 사용자 API·AI/RAG·Jira·DB를 거쳐 응답한다(mock 대체 없음).
2. 같은 시험 질문을 Discord의 등록 사용자로 보내고 같은 사용자에게 비공개 최종 응답이 도착한다.
3. 가린 추적 자료로 Discord interaction/request → 본체/하위 실행 → Jira 생성1·안내 종료 → DB completed/최종응답 저장을 연결한다.
4. R05가 답변·근거·확인된 접수번호·상태와 실제 자료를 대조하고 R01이 적용 버전과 함께 확인한다. 접수번호 표시는 공식 응답 계약/업무 경로를 따른다.
5. 원복 경로와 기존 P11/P19·기존 자료 보존을 확인하고, 알려진 실패/권한/시간/복구 한계를 별도로 남긴다.

이후 TC17/TC18·권한·중복·동시 요청·WF-11·시간 상한을 실제 시험한다. TC07 재개는 미구현이며 fail/DLQ resolve가 원 요청 재개를 뜻하지 않는다. 이 PR의 정상 목표 완료로 전체 기능 통과나 미구현 제외를 승인하지 않는다.

TC17/TC18 준비 인계는 P19 경로/게시, 동일 scope의 예외 사본/errors 연결, 종료 고장 주입/해제, 기존 문의 unknown/DLQ pending 읽기 조회 방법이다. R05는 네 항목 확인 전 --ready를 쓰지 않는다. 종료 고장 도구는 원 ID·Webhook 경로를 유지하므로 R01이 별도 ID·경로를 부여한다. 해제는 비활성화만이 아니라 정상 handoff 호출 대상으로 복귀·해시 확인까지 포함한다.
