# PR36 로컬 통합 후보

2026-11-07 / R01 / P09·P12·P18·P19·P20·P22·P28. 사용자 지시에 따라 R01이
기능 경로를 대리 편집하고 역할별 최종 확인은 후보 고정 뒤 취합한다. 원본 역할은 헌장을
유지한다. 이 문서는 main 병합·VM 배포·공식 전체 통과 선언이 아니다.

## 통합한 변경

- PR43 LLM/시간 고장 도구, PR44 본체 후속/facts/조회 소비 계약, PR45 RAG 인계·로컬 지연
  측정 도구를 선별 수용했다. PR45 도구는 독립 로컬용이며 공유 VM에 직접 실행하지 않는다.
- R05 cases/runner/verdict/result/search 브랜치를 경로별로 비교했다. 기존41개 정의,
  최초 실패와 반복 결과, recovery/not_implemented 구분을 보존했다. 원본 PR의 고유
  runs 자료는 바이트 그대로 수용하고 내용이 다른 후속 보고는 별도 보존·추가 기록했다.
- J01 실제 records provider, J02 본체 후속 처리, J03 검증된 문의 문맥 복원·최종 save를
  같은 계약으로 묶었다. 공개 version/expected_case_version은 null, 댓글 revision은 내부 값이다.
- 005/006을 보존한 새008/009, 전용 읽기 역할, PG 연결/쿼리 제한과 사용자 API 이미지를 준비했다.
- 팀 인증 헤더의 저장 이전 제거와401 계약을 위한 고정 n8n 이미지 후보, 운영 오류 알림,
  제한적 답변 검증 보완과 단일 경계 고장 사본 생성기를 추가했다.

## 로컬 검증 범위

Code/단위시험, JS·Python 공격 fixture 대조, 실제 격리 PostgreSQL 신규/업그레이드·권한·
동시 begin·쿼리 제한, provider의 실제 DB 드라이버 연결(Jira는 mock), 컨테이너 이미지
빌드/비권한 사용자 health를 확인했다. 실제 격리 n8n에서는 인증·원문 키 저장 경계와
HTTP 댓글 페이지 처리를 확인했다. 수치·해시와 최초 실패/수정 후 결과는
[이번 로컬 결과](../runs/public/20261107-135434-local-pr36-acceptance/report.md)에 기록한다.

위 검증은 팀 VM·실제 Jira/LLM·전체 P19·Discord 재시험을 대신하지 않는다.
RAG의3초 검색 흔들림 원인은 아직 실측 전이다. 모델 의미 판단과 전체 시간 상한도
실제 반복/고장 시험에서 다시 판정한다. 자동 재개 드라이버는 추가하지 않았다.

## 반입 전 필요한 비공개 구성

1. 기존 n8n/DB/API/봇 Compose·env·volume·암호화키·이미지와 원복 백업.
2. 실제 DB 실행 로그인과 API 전용 읽기 로그인/DSN. 009의 runtime_role에는 실제
   실행 로그인을 지정하고 기존 NOLOGIN 그룹의 권한을 암묵적으로 넓히지 않는다.
3. 실제 Jira 서비스 작성 계정 허용목록(배정 계정과 구별), support/security 배정 매핑,
   HTTPS Jira origin과 Credential 연결. 미치환 후보는 활성화하지 않는다.
4. 기존5명 사용자 override·Discord 매핑. 사용자 API image 교체로 등록값을 초기화하지 않는다.
5. 같은 scope의 support/state/DLQ/handoff/errors ID와 Error Workflow 지정, 대상 Webhook.
   운영 오류 알림과 Jira 담당 알림의 대상·API 수락·실제 수신을 구분한다.

## 다음 단계의 중단 조건

- 최신 main/원본 head·파일별 수용 증거·전체 diff/검사 확인 전 원본 PR을 종료하지 않는다.
  다른 역할의 최종 확인을 이미 받았다고 기록하지 않는다.
- 검토된 main만 반입한다. n8n 이미지 변경은 프로세스 재시작이 필요하므로 공유 n8n의
  활성 실행과 유지보수 창을 확인한다. 작업 중인 사본을 덮거나 별도 stack을 임의로 만들지 않는다.
- 보안 전용 단계에서 현재 팀/내부 키의 소비처 동기화·교체·새키 성공/구키401 거절·새 저장
  검증을 마친 뒤 업무 시험을 연다. 과거403 고정 기대를 가진 비공개 교체 도구도 먼저 수정·검증한다.
- SQL→API→state/handoff→support→검색/색인→봇 순으로 호환 묶음을 반입한다.
  새 SQL과 구 앱을 임의 혼합하지 않으며 원복은 검증된 호환 조합을 사용한다.
- 고장 사본 ID/경로·켜기/끄기·독립 해제 확인과 신규 본인/타인 조회 fixture를 준비한 뒤
  기존41개·권한7개·추가 경계·반복 시험을 수행한다. 해제 실패는 halted다.
- 과거 partial_effect/unknown/DLQ와 Jira 건을 새 성공으로 덮거나 일괄 삭제하지 않는다.
  자동 재개 미구현과 미실행/FAIL/PASS* 조건을 결과서에 남긴다.

원격 push·병합·PR 종료·VM 변경은 이번 로컬 작업에 포함하지 않았다.
