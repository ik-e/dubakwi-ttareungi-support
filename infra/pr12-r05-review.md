# PR #12 R05 검토 취합 (2026-11-05 KST)

사용자가 전달한 R05 팀 채팅 답변을 R01이 취합한다. GitHub 승인 리뷰나 R05 공식 실행 판정을 대신하지 않는다. 대상은 [P11 VM 부분 시험 요약](../runs/public/20261105-110022-vm-p11-publish/summary.json)과 [보고서](../runs/public/20261105-110022-vm-p11-publish/report.md)다. 기존 증거·해시·실행 결과는 수정하지 않았다.

R05는 준비·관측 기록 범위 병합에 이견이 없다고 밝혔다. 5유형×2경로=10/10, 유효 키 입력3유형×2경로=저장 실행6건, 인증 거절4건의 실행 미생성, B01→B02→B03→B33→B35→B36 및 B04/M01 호출0, B35 타임아웃6건 분리, invalid_input과 세부 codes, 공식 판정 아님/미실행 범위 표시를 확인했다. P11에는 LLM/티켓 노드가 없으므로 완성본에서 호출0을 재시험한다.

## 증거 해석 보완

- LN06은 **WF-08 유형 주입 시험**이다. 원 시험 도구의 “R05 WF08 문장” 명칭만으로 cases/common.json의 WF-08과 동일 입력이라고 해석하지 않는다. R05에 따르면 LN03 공백 질문과 LN04 501자는 WF-13a/13c 입력과 같다. 과거 시험 도구·보고서의 원본은 보존한다.
- 기존 elapsed_ms 약1.6초 및 첫 유효 키 응답 약4.8초는 부분 시험의 원 관측값이다. B35 data-api 타임아웃 대기가 포함됐을 가능성은 추정이며 원인을 새로 확정한 것은 아니다. 이 값은 **정상 서비스 응답시간 성능·SLA 판정이나 WF-11 통과 근거로 사용하지 않는다.** data-api 연결 뒤 별도로 재측정한다.

## 후속

R05는 data-api 연결 후 run_cases.py로 WF-08·WF-13a·WF-13c를 --no-hooks로 실행하고, 이어 WF-13b를 실행해 새 공식 기록을 남길 예정이다. 이번 검토는 그 실행 완료를 뜻하지 않는다. R04 저장/복구·data-api 영향 검토는 아직 취합되지 않았으므로 PR #12는 초안을 유지한다.
