# PR36 파일 수용·설계·로컬 완료 기준 대조

2026-11-07 / R01 / P09·P12·P18·P19·P20·P22·P28. 사용자 지시에 따라 PR36 전용 작업 트리에서 대조했다. 원격 push/병합/PR종료·VM·실제 Jira/Discord를 변경하지 않았다.

## 원본 수용 결정

열린 원본10개 PR의95개 PR-파일 항목을 모두 수용·대체·역사 보존·명시적 제외 중 하나로 판정했다. [파일별 표](pr36-source-acceptance.md)를 따른다. 최신 PR44 6b19fc4의 문서2줄도 수용했다. 원본 그대로 복사한 파일만 수용으로 간주하지 않고 현재 계약으로 대체한 경로와 사유를 남겼다. PR 없는 R054브랜치와 PR36 자체/새 파일도 전체 후보 manifest에 포함한다.

## 설계 대조

기존64개 요구와 원래 완료 조건을 [현재 대조표](contracts/pr36-local-design-verdict.json)에 연결했다. 기존 조사표의 과거 판단을 덮어쓰지 않았다. 각 행에 현행 구현 경로·로컬 검사·실제 배포/판정 잔여가 있다. S10 자동 재개는 미구현 한계이며 성공으로 세지 않는다.

대조 중 추가 수정한 내용:

- B08의 비null 공개 SupportCase.version과 B28의 비null TicketResult.case_version을 거절한다. 양성 mock의 잘못된 물리 버전은 null로 교정하고 거절3사례를 추가했다.
- wait도 context_saved 확인을 요구한다. 티켓 생성만으로 보완 대기 처리를 성공으로 세지 않는다.
- 실제 records 조회는1.2초 내부 마감·1.25초 응답 대기를 사용하며 오래 남는 읽기는 최대4개다. 막힌 읽기에서도503을 반환하고 추가 작업은 큐에 쌓지 않는다.
- 인증 HTTP 회귀 기대값을 새 보안 후보의401에 맞췄다. 기존403 실행 이력은 변경하지 않았다.
- 공식 설계·제출 요약·헌장 대리 편집·진입 링크와 PR24 당시 발표 대본/VM 후속 이력을 동기화했다. PDF/GIF 공개 예외를 추가하지 않았다.

## 체크리스트 판정

원래234개 체크 문장을 유지해 항목별로 판정했다. 현재 로컬에서 충족한173개, 로컬 부분은 확인했으나 실제 구성/외부 서비스/원본 자료 확인이 남은25개, VM·최종 병합/회신/동결36개로 분리한다. 복합 조건을 로컬 부분 통과만으로 체크하지 않았다. 전체 프로젝트 완료 기준234개가 모두 통과했다는 뜻이 아니다.

실행 명령·정확한 시험 건수·최초 실패/수정 후 결과·해시는 새 `runs/public` 결과에 기록한다. 격리 DB의 구/신 dump복원·권한 재적용·구버전 계약 원복·강제 마이그레이션 실패 보존을 추가 확인했다. AUTH01~07은 실제 B05→B13→RAG Validate Code의 모의 경계이고 실제 검색 권한 종단 통과가 아니다. 고장 사본18개와 소유자별 조회 fixture2개 생성 절차는 준비했으며 실제 생성/게시는 하지 않았다.
